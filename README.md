# 海克斯大乱斗 · 英雄对决

原创的俯视角 3D 单路 5V5 英雄竞技原型。支持最多 10 名真人同房间对战，空位由 AI 补齐；也可单人操控「苍锋」与九名 AI 对战，摧毁敌方水晶获胜。

## 4.0 引擎与画面

- 新版全屏战场、悬浮计分板、可展开阵容与强化面板，以及适配手机的底部游戏 HUD。
- 使用 Babylon.js / WebGL 2，原创程序化建模；模型拥有真实体积、材质与光照。
- 五种职业有独立的铠甲、披风、头饰与武器：发光剑刃、盾牌、长弓、法杖及治疗者光环。
- 英雄具有行走、转向、挥击和护盾动画；阵容头像直接由同一套 3D 模型离屏渲染。
- 长桥包含石砖凹凸材质、积雪城垛、桥墩、冰柱、雪松与峡谷；水晶、防御塔、技能和弹道有发光效果。
- 使用正交俯视镜头、环境反射、实时柔和阴影及飘雪。滚轮或地图左下角的加减按钮可缩放。
- 点击与技能落点通过相机射线计算，屏幕坐标和战斗坐标相互独立。

## 技能动作

英雄采用独立技能动作：剑斩转身挥剑、护盾举臂下蹲、突进前倾冲刺、大招蓄力跃起与落地收势；电脑英雄具有拉弓、举杖施法、治疗和重击动作。动作与特效使用同一对局时钟，暂停时一起冻结，阵亡与复活清除残留动作。突进和跃起仅插值表现位置，保留已有伤害与位移规则。

## 战斗特效

玩家 Q 使用旋转剑气与火花，W 形成护盾穹顶与上升光环，E 留下三层光带及残影，R 具有陨落能量、落地光柱和扩散冲击波。电脑英雄的范围法术、坦克震地、射手齐射、辅助治疗分别显示独立效果；友方以蓝青色、敌方以红粉色区分，治疗带有连接施法者的光束。英雄受击时闪光并迸出火花，远程弹道带有方向尾迹。所有视觉效果随战斗时间推进，暂停时冻结，结束后释放资源。

## 多人对战与本地启动

安装 Node.js 22+，运行 `npm ci`，然后 `npm start`，访问 http://localhost:5173。该服务同时托管页面与 WebSocket 对战，局域网朋友可访问 `http://你的局域网IP:5173`。

点击顶部「多人对战」，输入昵称及相同房间码后创建或加入房间。首名玩家进入蓝方，随后交替分配两队；总共 10 个英雄，不足的席位自动使用 AI。后来加入的玩家接管空闲 AI 英雄并保留当前等级与战局。WebSocket 掉线或主动离开房间后立即交给 AI；重新加入会分配空闲席位，不保证原席位。满 10 人后拒绝继续加入。可在房间面板复制邀请链接，链接包含服务器地址及房间码。

服务器以 30 Hz 统一计算移动、战斗、经验、技能、强化与购买，以 10 Hz 同步状态。客户端只能下达自己英雄的操作，无法上传血量、伤害或位置。WebSocket 无法建立时自动切换 HTTPS 轮询，同样进入原有房间；冷启动最多等待约 90 秒。HTTPS 会话关闭时立即释放，异常失联约 15–25 秒后由 AI 接管。多人局不支持暂停；选择海克斯和打开商店时战场继续运行。每位真人独立选择强化、加点和购买装备；红方在右侧泉水购买。当前真人共用 Q/W/E/R 手动技能组，AI 保留各自职业技能。房间仅存于内存，服务器重启后清空；无真人的房间在 30 秒后回收。

`npm run start:static` 仅启动静态单人版本。Babylon.js 已放在 `vendor/`，不依赖外部 CDN，许可见 `vendor/BABYLON-LICENSE.md`；执行 `npm run vendor` 可从固定版本依赖重新生成文件。

### 连接诊断

多人房间面板提供连接诊断与复制按钮，记录 WS 地址、耗时、error/close 事件、关闭码、关闭原因以及 HTTPS 回退。勾选「仅测试 WS」可停用回退。健康检查会按随机尝试编号返回对应的服务端 Upgrade / accepted / close 记录，帮助区分请求未到达服务端和服务端主动关闭；不包含昵称、房间码、会话令牌。浏览器不开放 WS 握手 HTTP 状态，日志不会把 1006 直接解释为特定故障。

### 公网部署

**GitHub Pages 无法运行对战服务器。** 仓库提供 `render.yaml` 与 `Dockerfile`，可部署到支持常驻 Node.js 与 WebSocket 的服务。直接在服务器域名打开游戏会自动连接同域服务器，无需再配置地址。

- Render：在 [Render Blueprint](https://render.com/deploy?repo=https://github.com/guo-jing/hks) 导入仓库，使用根目录 `render.yaml` 创建服务；完成后在分配的 HTTPS 地址打开游戏。
- 自建：运行 `PORT=8080 npm start`，通过支持 WebSocket Upgrade 的反向代理配置 HTTPS，或使用 Docker 构建并映射 8080 端口。健康检查为 `/health`，WebSocket 路径为 `/ws`。
- 继续使用 GitHub Pages：在多人面板输入 `wss://你的服务器域名`；也可把该地址写入 `config.js` 的 `window.HEX_SERVER_URL` 并推送，供所有玩家默认使用。HTTPS 页面需要连接 WSS。邀请链接会携带所选服务器地址。

GitHub Pages 默认连接 `wss://hex-heroes.onrender.com`；在 Render 的集成游戏页面则连接同域服务。首页与右上角都有多人入口，首页显示版本号；`/health` 也返回服务器版本，便于确认部署是否更新。房间码用于朋友约战，尚无账号、排位与跨进程房间持久化。

技能瞄准提示：悬停技能可预览，点击 Q/E/R 按钮进入瞄准。Q 显示真实扇形角度，E 显示突进通道与终点，R 显示最大施法距离和落地区域；红色提示冷却、法力不足或尚未学习。Esc 取消。

| 操作 | 效果 |
| --- | --- |

| 右键敌人 | 锁定普攻，超出距离自动追击 |
| 左键单位 | 查看目标生命 |

| W | 开启护盾 |
| E | 向鼠标位置突进，伤害沿途敌人 |
| R | 向指定区域施放延迟落地的大招 |

## 对战规则

- 双方每 18 秒派出一波小兵，防御塔优先攻击小兵。
- 在敌塔范围内伤害敌方英雄会吸引塔的仇恨。
- 敌方单位在附近阵亡时获取经验；亲手击杀获取金币和补刀。
- 英雄 3 级开局，最高 18 级；经验门槛采用 LOL 的递增曲线，3→4 需要 480 经验，此后每级增加 100，17→18 需要 1880。
- 每秒获得 12 被动经验；附近敌方单位阵亡提供共享经验，九名 AI 使用相同机制。经验来源和战斗数值针对本原型调整。
- 海克斯仅在开局（3 级）、7、11、15 级触发，每轮三选一，每局最多四个，每个强化本局仅能选择一次。普通升级不会弹出海克斯面板。
- 普通升级增加基础属性并给予一个技能点；Q/W/E 各最多 5 级，大招 R 在 6/11/16 级可升至 1/2/3 级。点击技能上方 ＋ 或按 Shift+技能键加点。
- 阵亡保留等级、技能与强化；阵亡期间解锁的强化会在复活后显示，已选轮次不重复。
- 泉水恢复生命与法力，可购买三种装备，每种限购三次。
- 英雄阵亡后复活。先摧毁防御塔才能伤害水晶。
- 双方比分统计整队英雄击杀；个人助攻只计算最近 10 秒内实际伤害过该敌人的英雄。
- 支持单人模式和最多 10 名真人的房间对战，空位由 AI 补齐；尚无手动英雄选择。

## 检查

`npm run check` 检查游戏、渲染器、联网客户端及服务器语法。
`npm run test:multiplayer` 启动临时服务器，验证两客户端同步、10 人上限、房间隔离、技能与强化、掉线 AI 接管和后来玩家补位。
`node tests/browser-multiplayer.mjs` 在本地 Chromium 9222 端口及 5175 测试服务器上验证两个真实页面的联网流程，使用 `MULTIPLAYER_URL` 可修改服务器地址。
`npm run test:browser` 使用本地 Chromium 的 DevTools 端口验证 5V5、技能、计分和复活，并验证 WebGL 网格、3D 点击、相机缩放、触屏施法与三分钟对局模拟。运行方法见 `tests/browser-smoke.mjs` 顶部。无 GPU 的环境可使用 Chromium 的 SwiftShader 软件渲染。

## GitHub Pages

仓库 Settings → Pages → Source 选择 **GitHub Actions**。首次启用后，在 Actions 里运行 **Deploy game to GitHub Pages**；之后推送到 `main` 自动发布。工作流会一并上传游戏脚本、3D 渲染器和 `vendor/` 引擎文件，支持 `/hks/` 子路径。

部署成功后地址：https://guo-jing.github.io/hks/
